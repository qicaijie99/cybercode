标题：Claude Code太吃Token了

最近这段时间，我几乎每天都在用 Claude Code 写项目。

它确实能干，但用久以后我发现，它也真的很能吃 Token。

有一次我只是想改一个设置按钮。它先搜项目、读文件、跑测试，终端又吐出一大段日志。等我换个说法继续改，前面的搜索结果、文件内容和测试输出又跟着新一轮一起进了上下文。

那一刻我感觉自己请了一个按字收费的装修师傅。我只是想换个门把手，他每次进门都要先把整套户型图重新念一遍。

我最早只会在提示词里加一句“请简洁回答”。后来才发现，真正的大头经常发生在回答之前。

于是我开始一项项处理。

第一，先清理多余空行和重复系统提示，别搬家时连空纸箱也付运费。

第二，长对话只保留任务目标、关键决定和最近上下文，压缩过期结果。我的本地记录仍然完整，裁掉的只是发给模型的副本。

第三，先压缩终端输出。模型通常不需要三千行日志，只需要知道成功没有、哪里失败、关键报错是什么。

第四，给 AI 一张代码地图。代码图谱先告诉它模块、函数和调用关系，再决定读哪些源码，不用为了找路把整栋楼都逛一遍。

第五，少说套话，也少造轮子。回答说重点，写代码优先复用已有实现和标准库。

这些方法单独配置并不难，但每次找工具、改提示词、接流程，我自己也嫌麻烦。后来我干脆把它们都做进了 CyberCode。

你可以把 CyberCode 理解成一个集成这些省 Token 方法、采用 Claude Code 式工作流的开源桌面端。Lite 清理、智能裁剪、RTK 输出压缩、响应压缩、少造轮子的实现策略和本地代码图谱，都可以直接开关。

我也踩过坑：优化不是开得越多越省。短任务有时会被检索和摘要的固定成本反向增加消耗。所以我现在先开 Lite、RTK 和代码图谱，长对话再打开均衡档智能裁剪。

省 Token 不是让 AI 少干活，而是少让它反复读废话、翻旧账，再抱着三千行日志徒步旅行。
